# Субагенты и изоляция контекста

Субагенты — один из мощнейших инструментов оптимизации токенов. Они работают в отдельном окне контекста, защищая ваш основной разговор от раздувания.

## Как работают субагенты

```
Основной разговор (200K контекст)
    ↓ порождает Agent
Субагент (своё 200K окно)
    ↓ тяжёлое исследование
    ↓ читает много файлов
    ↓ запускает поиски
    ↓ возвращает саммари
Основной разговор получает: компактное резюме (~сотни токенов)
```

Полное исследование субагента (потенциально 100K+ токенов) **не** добавляется в основной контекст.

## Типы агентов

| Тип | Назначение |
|-----|-----------|
| `Explore` | Быстрое исследование кодовой базы |
| `Plan` | Архитектурный дизайн, планирование |
| `general-purpose` | Многошаговые задачи |
| `golang-pro` | Go-разработка |
| `backend-developer` | Backend API |
| `rust-engineer` | Системное программирование на Rust |

## Когда использовать

### Используйте субагент когда:
- **Исследуете незнакомый код** — агент читает файлы, вы получаете резюме
- **Ищете паттерны** — "найди все места где используется X"
- **Параллельные расследования** — запускайте несколько агентов одновременно

### Не используйте когда:
- Вы уже знаете точный файл и место
- Задача — простое чтение или редактирование

## Пример экономии

**Без субагента** (исследование в основном контексте):
```
Read файл A (5K) + Read файл B (8K) + Grep (3K) +
Read файл C (6K) + Read файл D (4K) = 26K токенов в основном контексте
```

**С субагентом:**
```
Агент исследует: 26K (в своём контексте)
Возвращает резюме: ~500 токенов в основной контекст
Экономия: 25,500 токенов
```

## Советы

1. **Давайте чёткие промпты** — размытые → широкие исследования → лишние токены
2. **Указывайте — исследовать или реализовать** — агент не знает ваш замысел
3. **`Explore` для быстрых поисков** — оптимизирован для скорости
4. **Параллельные агенты** для независимых задач
5. **Максимум 3 агента** — больше не всегда лучше
