# Лимиты результатов инструментов

Результаты инструментов (содержимое файлов, вывод bash, результаты поиска) — часто крупнейшие потребители токенов контекста.

## Лимиты размеров (из `toolLimits.ts`)

| Лимит | Значение | Что происходит при превышении |
|-------|----------|------------------------------|
| **На инструмент** | 50,000 символов | Сохраняется на диск; Claude получает превью + путь |
| **На инструмент (токены)** | 100,000 токенов (~400KB) | Жёсткий лимит, результат обрезается |
| **На сообщение (агрегат)** | 200,000 символов | Самые большие результаты в пакете → на диск |

### Бюджет на сообщение

При параллельных вызовах инструментов (Claude читает 5 файлов одновременно):

```
5 файлов × 40K символов = 200K → ровно в бюджете
5 файлов × 50K символов = 250K → крупнейшие файлы обрезаются
```

## Типичные «тяжёлые» операции

| Операция | Типичная стоимость | Как уменьшить |
|----------|-------------------|---------------|
| `Read` файла на 1000 строк | 5,000-15,000 токенов | Используйте `offset` + `limit` |
| `Bash` с большим выводом | 5,000-50,000 | Пайпите через `head` или `tail` |
| `Grep` с множеством совпадений | 5,000-30,000 | Конкретнее паттерны, `head_limit` |
| `WebFetch` больших страниц | 10,000-50,000 | Целевые URL |

## Советы

### 1. Читайте только нужное
```
Плохо:  "Прочитай весь конфиг"
Хорошо: "Read src/config.ts строки 45-80"
```

### 2. Ищите конкретно
```
Плохо:  "Найди обработку ошибок в проекте"
Хорошо: "Grep 'catch.*Error' в src/services/*.ts"
```

### 3. Не используйте Bash для поиска файлов
```
Плохо:  "Запусти find . -name '*.ts' | xargs grep 'TODO'"
Хорошо: "Grep 'TODO' в *.ts файлах с head_limit 20"
```

### 4. Ограничивайте вывод Bash
```
Плохо:  "Запусти npm test"     (тысячи строк)
Хорошо: "Запусти npm test 2>&1 | tail -50"
```
